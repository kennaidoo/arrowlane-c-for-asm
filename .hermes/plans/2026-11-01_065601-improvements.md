# Improvements for arrowlane-c-for-asm

## Goal

Close most of the 3.6 times encode gap against the C++ port by fixing one function,
and make the repository's claims harder to break by adding sanitizers, a fuzz test
and a formatter corpus.

## Current context

Measured tonight on one machine, 200,000 rows, Release, five repeats:

| Implementation | Wire bytes | Encode ms | Decode ms |
|---|---|---|---|
| Python reference | 42,505,756 | 2,131.7 | 2,081.9 |
| C++ port | 42,505,784 | 244.7 | 827.4 |
| this project | 42,505,756 | 885.6 | 37.9 |

The bytes agree exactly, so the encode gap is time, not correctness. It sits in one
place: `src/json_fixture.c:81`

```c
for (int precision = 1; precision <= 17; ++precision) {
    snprintf(scratch, sizeof scratch, "%.*g", precision, value);
    if (strtod(scratch, NULL) == value) {
        w_text(w, scratch);
        return;
    }
}
```

A double that needs 16 digits runs sixteen `snprintf` calls and sixteen `strtod`
calls. At 200,000 float values that is most of the 885 ms.

Everything else is already tight: the frame, the header and the fixture are one
pass each, and the checksum has an assembly kernel.

## Architecture / proposed approach

The search for the shortest round-tripping precision is monotonic, so it does not
need to count upwards. A binary search over the same precisions finds the same
answer in about five steps instead of up to seventeen, and because it returns the
same precision the output bytes cannot change. The existing 200,000 row byte
identity test is the guard that proves it.

## Task 3: the binary search

### 3.1 Change the loop

In `src/format.c`, replace the upward search with a binary search over the same
range. Round-tripping is monotonic in precision: if `p` digits read back as the
value, then `p + 1` digits also do, because more correct digits cannot move the
result away from the value. So the smallest `p` that round-trips can be found by
halving the range.

```c
    /* The shortest precision that reads back as the same double. Monotonic, so a
     * binary search finds the same answer the upward scan did, in about five
     * attempts instead of up to seventeen. */
    int low = 1;
    int high = 17;
    int best = 17;
    char best_text[40];
    snprintf(best_text, sizeof best_text, "%.17g", value);
    while (low <= high) {
        const int middle = (low + high) / 2;
        char candidate[40];
        snprintf(candidate, sizeof candidate, "%.*g", middle, value);
        if (strtod(candidate, NULL) == value) {
            best = middle;
            memcpy(best_text, candidate, sizeof best_text);
            high = middle - 1;
        } else {
            low = middle + 1;
        }
    }
    w_text(w, best_text);
```

Keep the two special cases above it unchanged.

## Task 4: sanitizers and a fuzz test

### 4.1 The fuzz test

Create `tests/fuzz_frame.c`:

```c
#include "aln.h"

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* A fixed seed keeps the run reproducible; the point is coverage, not luck. */
    uint32_t state = 0x9E3779B9u;
    uint8_t buffer[512];
    int decoded = 0;
    for (int round = 0; round < 20000; ++round) {
        const size_t length = 38u + (state % (sizeof buffer - 38u));
        for (size_t index = 0; index < length; ++index) {
            state = state * 1664525u + 1013904223u;
            buffer[index] = (uint8_t)(state >> 16);
        }
        /* Half the rounds start from a valid prefix, so the parser reaches deeper. */
        if ((round % 2) == 0) {
            buffer[0] = 'A';
            buffer[1] = 'L';
            buffer[2] = 'N';
            buffer[3] = '1';
            buffer[4] = 1;
            buffer[5] = 1;
        }
        struct aln_frame frame;
        if (aln_frame_decode(buffer, length, &frame) == ALN_OK) {
            ++decoded;
            /* A frame that passed must have its checksum covered, so re-encoding
             * its payload must produce the same checksum. */
            const uint32_t crc = aln_crc32(frame.payload, (size_t)frame.payload_len);
            if (crc != frame.crc) {
                printf("FAIL: a frame passed with a checksum that does not match\n");
                return 1;
            }
        }
    }
    printf("ok: 20000 frames, %d accepted, none crashed\n", decoded);
    return 0;
}
```

## Task 5: base64 decoding belongs to the library, not the test

`tests/aln_test.c` decodes the schema blob with a hand written loop that also
mutates the length while trimming padding. It works and it is fragile.

### 5.1 Declare and implement

In `include/aln.h`:

```c
/* Decodes standard base64 with padding. Returns the byte count, or 0 on bad input. */
size_t aln_base64_decode(const char *text, size_t len, uint8_t *out, size_t cap);
```

In `src/base64.c`, implement it with strict checks: length a multiple of four, only
the alphabet plus `=` at the end, and no byte written past `cap`.

### 5.2 Test it

In `tests/aln_test.c`, replace the inline loop with `aln_base64_decode`, and add:

```c
static void test_base64_round_trip(void) {
    uint8_t raw[64];
    for (size_t index = 0; index < sizeof raw; ++index) {
        raw[index] = (uint8_t)(index * 37u);
    }
    for (size_t length = 0; length <= sizeof raw; ++length) {
        char text[128];
        uint8_t back[64];
        CHECK(aln_base64_encode(raw, length, text, sizeof text) == ((length + 2) / 3) * 4);
        CHECK(aln_base64_decode(text, strlen(text), back, sizeof back) == length);
        CHECK(memcmp(raw, back, length) == 0);
    }
    CHECK(aln_base64_decode("A", 1, raw, sizeof raw) == 0);
    CHECK(aln_base64_decode("!!!!", 4, raw, sizeof raw) == 0);
}
```

Expected: the suite goes from 68 checks to about 75, all passing.

## Risks, tradeoffs and open questions

1. **The binary search changes behaviour only if the corpus disagrees.** The
   monotonic argument is sound, and the 200,000 row byte count is an independent
   check. If the wire size moves at all, stop and treat it as a defect.
2. **The corpus pins the reference's own output, including its quirks.** That is the
   point, and it means the corpus has to be regenerated if the reference's encoder
   ever changes.
3. **Sanitizers and Fortran.** AddressSanitizer links fine with gfortran on Debian
   bookworm, but if the link fails, run the sanitizer build with `ALN_ASM_CRC32=OFF`
   and note it, rather than dropping the check.
4. **The decode gap is still not addressed.** Parsing NDJSON into columns is a
   parser and a schema, and it is a separate project. The honest fix tonight is to
   name the column correctly, not to claim a win.
5. **Schema synthesis and the ipc lane remain absent.** Both are larger than
   everything above combined, and neither is needed for the claim this repository
   makes.
